# Plan: Noguchi Modular Synth

Based on the current direction in `notes/brainstorm.md`: one central **Core** sound engine (Teensy 4.1 #1 + audio shield, BRS40 speaker in the base column), plus snap-on effect modules. The heavy **Space/Ear** module carries Teensy 4.1 #2. Stacking vertically means series inserts, snapping horizontally means parallel sends.
Updated 2026-10-30.

**Software stack** (details in `notes/dsp_libraries.md`):
- **Teensy Audio Library** provides the scheduler and int16 basics.
- **OpenAudio_ArduinoLibrary** is the float32 graph: blocks, patch cords, I/O, converters, FFT, LMS.
- **DaisySP** (through our own `AudioStream_F32` wrapper) supplies the voices and light effects.
- **hexefx_audiolib_F32** supplies reverbs, delay and dynamics.
- **ConvolutionUP** handles the long IRs (int16, about 0.41 s, about 570 KB RAM, Teensy #2 only).
- **CMSIS-DSP** is for our own blocks.
- Added libraries stay local to the project. Never edit `Audio.h`.

## Part A: Audio / DSP (no CAD)

### Phase 1: Easy, get sound out and working
**1.1 Toolchain + first sound**
- Arduino IDE + Teensyduino, Teensy 4.1 + audio shield (SGTL5000), headphones on the shield's jack.
- Play a library test tone and confirm with `AudioMemoryUsageMax` / `AudioProcessorUsage` on Serial.

**1.2 ★ First task: three-waveform oscillator, on/off, master volume, pitch**

Parts (all owned):
| Part | Use |
|---|---|
| Teensy 4.1 + audio shield | |
| 1 × tactile button | Cycles sine → triangle → sawtooth |
| 1 × SS12D00G2 slide switch | Sound on/off |
| 1 × WH148 B10K pot | Master volume |
| 1 × WH148 B10K pot | Pitch (added 2026-10-30) |
| Breadboard + jumpers | |

Wiring suggestion (avoids the shield's pins 6–8, 10–13, 18–21, 23):
| Part | Teensy pin | Other side | Notes |
|---|---|---|---|
| Button | 2 | GND | `INPUT_PULLUP` |
| Switch | 3 | GND | `INPUT_PULLUP` |
| Volume pot wiper | A0 (pin 14) | Ends to 3.3 V and GND | Use 3.3 V, never 5 V |
| Pitch pot wiper | A2 (pin 16) | Ends to 3.3 V and GND | A1 (pin 15) is left free for the shield's VOL pad |

GND and 3.3 V come from the Teensy's own pins: wire them to the breadboard rails first.

Audio graph: `AudioSynthWaveform → AudioEffectFade (on/off) → AudioMixer4 (master gain) → AudioOutputI2S`, plus `AudioControlSGTL5000` (`enable()`, `volume(~0.6)` as a fixed headphone ceiling, `lineOutLevel()` for line out).

Behavior:
- **Waveforms:** `WAVEFORM_SINE`, `WAVEFORM_TRIANGLE`, `WAVEFORM_BANDLIMIT_SAWTOOTH`.
- **Button:** debounce it. Each press calls `begin(newWaveform)`.
- **Switch:** use it as an audio on/off. Ramp the gain to 0 or back over about 10 ms so there's no click. (A real power switch goes on the battery line later, in 1.4.)
- **Volume pot:** read it, smooth it (one-pole filter), and map it on a **dB curve** (e.g. −60 dB…0 dB → linear gain) rather than linearly, so the knob feels even (hearing perception, lecture 1–2). Only update when the value changes by more than a small threshold, to avoid zipper noise.
- **Pitch pot:** same smoothing, mapped **exponentially** (55 Hz…1760 Hz, 5 octaves), so equal turns give equal musical intervals (pitch perception, lecture 1–2).
- **Serial:** prints sound on/off, waveform, gain (dB) and frequency when they change. Typing `a` swaps the saw between band-limited and naive.

Done when: the button cycles all three waveforms, the switch mutes and unmutes cleanly, the volume knob sweeps smoothly with no clicks, and the pitch knob sweeps 55–1760 Hz.

Class bonus: A/B `WAVEFORM_SAWTOOTH` against `WAVEFORM_BANDLIMIT_SAWTOOTH` at high pitch (pitch knob up, `a` in Serial) and record both. It's the aliasing demo from lab 1, Exercise 6.

**1.3 Playable voice**
- Pitch pot: done in 1.2.
- ADSR envelope (`AudioEffectEnvelope`), triggered by a button or a piezo pad (PVDF/piezo into an analog pin through a resistor/diode clamp).

**1.4 Standalone sound**
- Shield line out → class-D amp (PAM8403-class, *to buy*) → BRS40.
- USB power bank, with the power switch on the supply line.
- Boot straight into the patch.

**1.5 Baseline metrics**
Log CPU and memory per block to Serial (later to the ST7789). This becomes the evaluation baseline.

### Phase 2: Mid level, quick and cheap effects and functions
**2.0 Move to the F32 graph**
- Install OpenAudio + hexefx, and write the DaisySP `AudioStream_F32` wrapper template.
- Port the 1.2–1.3 sketch over to the F32 graph.

**2.1 Library effects in a chain**
- DaisySP: svf / moogladder, bitcrush / decimator, chorus, overdrive.
- hexefx: stereo delay, plate reverb, compressor.
- Each effect gets 1–2 knobs. This proves the routing and gives quick sound.

**2.2 Own DSP ported from the labs (custom `AudioStream_F32` blocks)**
- Lo-fi (sample-rate + bit depth): lab 1
- 6-band EQ and biquad filters: lab 2
- Vowel / formant voice (Rosenberg pulse + formant filters): lab 2
- Noise and chirp sources: lab 1

**2.3 Engine functions**
- 4-voice polyphony, a simple step sequencer / arpeggiator.
- LFO modulation.
- Presets saved to the SD card or EEPROM.

**2.4 Chain manager**
- Software effect slots that can be reordered, with series inserts and parallel sends plus a return mix.
- Mute and crossfade when the chain changes.

**2.5 Module detection prototype (breadboard)**
- Wire 2–3 XIAO ESP32-S3s (owned) to the Core, one data line per face, and run HELLO / I_AM discovery to build the tree (`notes/module_topology.md`).
- The Core prints the tree, builds the series / split / sum audio graph, and crossfades on changes.

**2.6 Python reference tests**
Run the same input through the lab Python and through the Teensy (recorded via line in), then compare.

### Phase 3: High level, complex and intricate
**3.1 Modal voice**
- Strike the enclosures and record with a piezo.
- Fit the modes (frequency, decay, gain) in Python.
- Run a real-time modal resonator bank on the Core, excited by the piezo pads (lecture 6). Start from DaisySP `modalvoice` / `resonator` / `mode`, then load our fitted modes.

**3.2 Spectral effects**
STFT freeze, gate and blur as a custom `AudioStream_F32` using CMSIS `arm_rfft_fast_f32` (lab 1 STFT).

**3.3 Space module on Teensy #2**
- Analog audio link between the two Teensys (Core send → Space → return).
- **Hybrid reverb:** ConvolutionUP on the first ~0.4 s of the Tull / St Andrews IRs, plus a hexefx `ReverbSc` FDN tail matched to the measured RT60 (PSRAM, *to buy*).
- HRTF panner (lab 3).

**3.4 Ear**
- INMP441 mic.
- NLMS echo cancellation against the Core's own output, using CMSIS `arm_lms_norm_f32` (adaptive filtering lecture).
- GCC-PHAT clap direction with 2 mics (lecture 9), driving pan or modulation.

**3.5 Speaker correction**
Sine-sweep measurement of the BRS40 cabinet (lab 3 method), then a minimum-phase inverse FIR on the Core (OpenAudio FIR or ConvolutionUP).

**3.6 Stretch**
- Denoise / "musical noise" effect (lecture 10)
- Pitch tracking / autotune (upcoming lecture)
- Sound classifier (clap / voice / knock)

**3.7 Evaluation**
Python vs. Teensy error, latency, CPU per block, NLMS convergence (ERLE), localization accuracy, before/after speaker response.

## Part B: CAD / Fabrication (concise)

### Phase C1: Standards + form lock
- **C1.1** Lock the form language from the v4 sketch (slim uniform column → hourglass waist → cantilever → lantern cube / head).
- **C1.2** Write the **connector face standard** as a parametric Grasshopper definition: magnet size and pattern, 5-contact hermaphroditic layout (GND · 5 V · DATA · AUDIO_SEND · AUDIO_RETURN), and N/S magnet keying so any face mates with any face but never at the wrong rotation. Every module reuses it.
- **C1.3** Set the size grid (column footprint, slab heights) so modules stack and align.

### Phase C2: Fit prototypes
- **C2.1** 3D-print or laser-cut test faces to check magnet strength, pogo alignment and polarity.
- **C2.2** Core column mock-up sized for the BRS40 (about 1–3 L, sealed vs. ported test), Teensy + amp + power bank bay, and play-surface layout.

### Phase C3: Module enclosures
- **C3.1** Effect module shells from the face standard, with knob/LED layout, the RP2040 board bay, and cable paths.
- **C3.2** Heavy module (lantern cube or head) housing Teensy #2, the mic(s) and the cantilever mount.

### Phase C4: Final fabrication + documentation
- **C4.1** Final materials (plywood / acrylic / cast), finishing, assembly, strain relief.
- **C4.2** Blender renders and exploded views for the report and demo.
